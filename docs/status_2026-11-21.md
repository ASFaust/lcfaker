# Status 2026-11-21: the representation redo

What changed after the review of the paper draft, what it gave, and what is still open. Details and every
intermediate number: docs/journal.md (sections "part 2"); what the data is: docs/data_semantics.md.

## What the redo found

1. **All curves are validation curves**: three sources are losses (TaskSet, FCNet, bbomix), three are bounded error
   rates (JAHS, NAS-Bench-201, QuickTune). Plain log-loss is impossible for 21% of TaskSet tasks (negative
   log-likelihoods); the usable scale is log(loss − floor).
2. **The old S-curve in log-time was already a broken power law** (a logistic in log-time with a floor is exactly
   L + A / (1 + (t/τ)^a)). What had never been tested was the scale on which configs and noise act.
3. **The log-excess scale wins**: one component explains 84-94% of the within-task variation of log(loss − floor)
   (linear loss: 81-91%), and predictions of the final value from 40% of a curve are better (TaskSet rank corr.
   0.86 vs 0.80).
4. **Noise** grows with the excess on error-rate sources (multiplicative) but not on TaskSet losses (additive).
5. **Schedules matter**: time measured as cumulative learning rate (optimiser progress) predicts decayed-schedule
   curves better than step count (rank corr. 0.90 → 0.93 on adam8p). The learning rate is a partial time warp
   (curve time scale ∝ lr^−0.15).
6. **What makes curve speed predictable** differs by source: on TaskSet the learning rate (R² 0.58 alone, 0.90
   with the schedule and other hps; −0.15 without the learning rate); on JAHS not the learning rate at all (0.00),
   but architecture / augmentation (0.74).
7. **Rising validation curves**: 3.6% of live TaskSet curves, 11% on bbomix, ≈ 0 on cosine-annealed sources. On
   TaskSet most rises are instabilities (training loss rises too); classic overfitting (training improves,
   validation worsens) concentrates in some families (image convnets on small data: 73% of their rising curves).

## The new generator: bpl (curvefaker/faker_bpl.py)

Curves are broken power laws on the log-excess scale, in schedule-aware progress time:
y = L + d + A / (1 + (x/τ)^a), with x = lr^κ · (cumulative learning-rate multiplier of the config's schedule).
Dimension 0 of a generated search space is the log learning rate; for TaskSet-like tasks the schedule parameters
(decays, warm-up / cosine) are real config dimensions. Per-config parameters come from smooth random fields
through each task's real joint distribution, plus the task's real learning-rate relation (v13). Overfitting is an
explicit term; noise scales with the excess as measured per task; output is in raw units (loss or error rate).

Versions were changed one at a time (v1-v14, several tried and dropped; all in the journal). The current best is
**bpl-v13**.

**Main result**: the new generator reproduces how existing multi-fidelity HPO algorithms behave far better than
both the old model and the ifBO prior (regret error 0.015 vs 0.031 / 0.088; freeze-thaw gain 0.105-0.113 vs real
0.112). The old model's main defect, inconsistent early rankings, is largely gone.

## Open gaps (bpl-v13)

- **Curves converge too early** (time to 90% progress −1.8 vs −1.1; half the real late progress). Partly the
  record fits (a replay of real configs with their fitted curves is also early, −1.3), partly generation. A second
  slow stage (floor decaying as x^−b) fixed the replay but not generation.
- **Late noise too small relative to early** (0.04 vs 0.15): generated curves have a sharper first step and ~35%
  too little noise in the early-middle phase.
- **Too few rising curves** (1.4% vs 3.9%); the select reference has more than the fit records (bbomix 11%).
- **Landscapes** less predictable (0.68 vs 0.77) and speed only partly predictable from the config (0.49 vs 0.73).
  v10's learning-rate-aware matching fixed predictability (0.72) but cost HPO fidelity; v13 combines the smooth
  copula with the learning-rate relation and keeps HPO fidelity.
- Not done yet: the paper rewrite, the release update (the `publication` branch still holds swt-v11, marked draft).
